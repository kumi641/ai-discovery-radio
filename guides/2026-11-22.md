#### 実験：AIに作らせた自動化に「データの会計」を入れる

- **目的**：自動化スクリプトに件数の照合を入れ、データが黙って消えたら止まるようにする
- **使用ツール**：Claude Code（または同様のAIコーディング助手）、Python 3
- **必要な準備**：Claude Code などのAIコーディング助手が使える環境、Python 3、練習用の空のフォルダ
- **所要時間**：約30分
- **費用**：Claude Code の利用料（料金は未確認：公式の料金ページで確認）。Python は無料
- **無料の代替**：AIを使わず、記事の式「入力件数 = 成功 + スキップ + エラー」を自分でスクリプトの最後に書き足す

**手順**

1. 練習用フォルダでAIコーディング助手を起動し、「名前とメール欄がある10行ほどのサンプルCSVと、メール欄が空の行は飛ばして残りを別のCSVに書き出す小さなPythonスクリプトを作って」と頼む
2. スクリプトを一度動かし、出力のCSVができることを確かめる
3. 下のお願い文を貼り、記録・件数の照合・見本の表示を足してもらう
4. もう一度動かし、入力件数と「成功＋スキップ＋エラー」の合計が表示され、一致していることを確かめる
5. run_log.jsonl を開き、スキップした行に理由が書かれているかを見る
6. AIに「スキップの件数を数え忘れるように一時的に変えて」と頼んで動かし、照合で止まることを確かめてから元に戻す

**コピーして使うプロンプト**

```
このフォルダの自動化スクリプトに、次の3つを足してください。既存の処理内容は変えないでください。
1. 1行ごとの結果を run_log.jsonl に JSON Lines 形式で書く。項目は id、status（success / skip / error）、reason。
2. 最後に「入力件数 = 成功 + スキップ + エラー」を計算して表示し、合わなければエラーメッセージを出して終了コード1で止める。
3. 結果から先頭・末尾・ランダムの合計3件を選び、入力と出力を並べて表示する。
変更点の説明と、件数がずれたときに本当に止まるかの確かめ方も教えてください。
```

- **完成するもの**：理由つきログと件数の照合が入った自動化スクリプト
- **確認方法**：正常時は件数が一致して最後まで動き、わざとスキップを数え忘れさせたときは照合で止まって終了コード1になる

## 2. OpenAI、AIの能力を無断で抜き出して別のAIを育てる「adversarial distillation」への多層的な対策を説明

*最新AIニュース｜OpenAI・公開 2026-11-20 10:00｜評価 60/100*

出典：https://openai.com/index/combatting-adversarial-distillation

**結論**：OpenAI が、AIの答えや考えの途中を無断で集めて別のAIを育てる「adversarial distillation」への対策を説明しました。モデルの訓練、入力と出力の見張り、APIでの制限、組織的な悪用の検出と取り締まりを重ねています。開発者向けには、会話履歴を書き換えると考えの記録が捨てられるなどの影響があります。

### 重要ポイント

- **答えをまねて別AIを育てる悪用**：蒸留（distillation）は、あるAIの答えをお手本に別のAIを育てる方法。無断で行い、安全のブレーキを外したAIを作るのが問題になっている。
- **考えの途中は特に狙われやすい**：OpenAIの社内実験では、考えの途中をそのまま学んだAIの方が、要約だけを学んだAIより性能が高くなりやすかった。
- **訓練・見張り・取り締まりを重ねる**：抜き出しを断る訓練、入力と出力の見張り、組織的な悪用を見つけてアカウントごと止める仕組みを組み合わせている。
- **履歴の書き換えに影響あり**：新しいモデルでは、前のメッセージを書き換えると、そのあとの考えの記録がAPIで捨てられる。

### 技術解説

**何が新しいのか**：考えの途中（推論の記録）の保護を強めた点。新しいモデル（GPT-6.2 Astra と Sol）では、考えの記録をそれを生んだ会話履歴に結びつけ、前のメッセージを編集すると、その後の記録が捨てられる。

**なぜ重要か**：安全のための制限を外したコピーが出回ると、サイバー攻撃などに悪用されるおそれがある。同時に、正当な開発者のアプリの動きにも影響が出る可能性がある。

**従来との違い**：1回ずつのやり取りを守るだけでなく、たくさんのアカウントを使った組織的な動きをまとめて見つけ、ネットワークごと取り締まる。発見はやり取り単位の守りにも返される。

- 抜き出しの試みを見分けて断る訓練（攻撃例を学習に使う）
- 入力と出力の両方を分類器で見張り、ツール呼び出しの引数も確認する
- 考えの記録を、ユーザー・組織・モデルの種類をまたいで再利用できないようにする
- 固定の攻撃の再生と、相手に合わせて変わる自動の攻撃役で、守りの強さを測る

### 実践アイデア

- 自分のAIアプリが会話履歴を書き換えていないか見直す
- 出力が見張りで止められた場合のエラー処理を用意する
- 自分のAIサービスでも、大量の不自然な利用を見つける仕組みを考えるきっかけにする

## 3. Qiita：Claude Code が「JavaScript heap out of memory」で落ちたときの対処（--continue で再開、--safe-mode で切り分け、/heapdump で調査）

*エンジニアの実践ノウハウ｜Qiita・公開 2026-11-21 21:31｜評価 75/100*

出典：https://qiita.com/homhom44/items/e41dca096fb741f1b3b0

**結論**：Claude Code が作業中に「JavaScript heap out of memory」と出て落ちたときの手順を、公式ドキュメントと GitHub の issue をもとにまとめた記事です。再起動して会話を戻す、設定を切って原因を絞る、/heapdump で調べる、の順に対処します。

> 💡 **こう使うと面白い**：長い作業をAIに任せる日の前に、「警告が出たら終了して再開、くり返すならセーフモード」という3行の手順メモを手元に置いておくと、落ちても慌てずに済みそうです。

### 重要ポイント

- **本体のメモリ切れで落ちる**：「JavaScript heap out of memory」は、APIのエラーではなく Claude Code 本体のメモリが上限に達したという意味。
- **2.5GB超えで警告が出る**：公式ドキュメントでは、使用量が2.5GBを超えると警告が出る。落ちる前に対処できる。
- **--continueで会話ごと再開**：一度終了して claude --continue で起動すると、同じ会話を新しいプロセスで続けられ、メモリが空く。
- **--safe-modeで原因を絞る**：プラグイン・MCPサーバー・フックなどを切って起動し、メモリが減れば設定側が原因と分かる。

### 技術解説

**何が新しいのか**：公式のトラブルシューティングにある手順（2.5GBの警告、--continue、--safe-mode、/heapdump）を、実際のエラー表示と結びつけて1つの流れにまとめた点。

**なぜ重要か**：長い作業を任せている途中で落ちても、慌てずに会話を取り戻し、原因が自分の設定かどうかを見分けられる。

**従来との違い**：やみくもに再インストールするのではなく、再開・切り分け・記録の順で原因を絞り込む。

- セッションのヒープが2.5GBを超えると警告が表示される（公式）
- claude --continue で直前の会話を新しいプロセスで再開（公式）
- claude --safe-mode でプラグイン・MCPサーバー・フックなどを切って起動し比較（公式）
- /heapdump は ~/Desktop（無ければホーム）に .heapsnapshot と -diagnostics.json を書き出す。前者は会話や認証情報を含むので共有しない（公式）

## 4. Zenn：自動化の出力を信じる前に通す3つの検証ゲート（理由つきの実行ログ・件数の照合・差分とサンプルの確認）

*エンジニアの実践ノウハウ｜Zenn・公開 2026-11-21 16:21｜評価 66/100*

出典：https://zenn.dev/automation_lab/articles/automation-verification-gates

**結論**：自動化で本当に怖いのは、エラーで止まることではなく、何も言わずに間違った結果を残すことだと筆者は述べます。そこで、理由つきの実行ログ、件数の照合（データの会計）、人の目によるサンプルと差分の確認、という3つの関門を通してから結果を信じる方法を紹介しています。

> 💡 **こう使うと面白い**：AIに作らせた家計簿やファイル整理の自動化に「入力の数＝成功＋飛ばし＋失敗」の足し算チェックを1行入れると、こっそり消えた1件に気づけて面白そうです。

### 重要ポイント

- **怖いのは静かな間違い**：「正常終了」と出ても、データが更新されていなかったり空になっていたりすることがある。

- **先頭・末尾・ランダムを目で見る**：境界の先頭と末尾、特殊文字を含む行、複雑な分岐を通った行、ランダムな1件を確認し、差分で関係ない欄の変化も見る。
