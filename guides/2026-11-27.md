関連ニュース：Zenn：スキル（SKILL.md）のアンチパターン13選と直し方。長すぎる・網羅しすぎる・複数人で書き足して矛盾する、などの見つけ方と、あり・なしで比べる運用

#### 実験：自分のスキルの健康診断

- **目的**：手元のスキル（SKILL.md）を、記事と公式ガイドの観点で点検し、いちばん効く1か所だけを直して効果を確かめる
- **使用ツール**：Claude Code
- **必要な準備**：Claude Code が使えること、~/.claude/skills/ か、プロジェクトの .claude/skills/ にスキルが1つ以上あること（無ければ、よく頼む作業で1つ作っておく）、スキルの今の状態を git でコミットするか、フォルダごとコピーしておく（元に戻せるように）
- **所要時間**：約20分
- **費用**：Claude Code の利用枠の範囲

**手順**

1. 自分用のスキル置き場（~/.claude/skills/）と、プロジェクトのスキル置き場（.claude/skills/）に、どんなスキルがあるか確かめる
2. 直す前に、スキルが合いそうな頼みごとを1つ決め、Claude Code に2回頼んで、スキルが使われたかと結果をメモする
3. Claude Code に下のプロンプトを貼り、書き換えはせずに診断だけしてもらう
4. 出てきた表から「最初に直すべき1つ」だけを選び、自分で（または Claude Code に頼んで）直す
5. 同じ頼みごとをもう2回して、スキルが使われたかと結果を、直す前のメモと比べる
6. 良くならなかった場合は、コピーしておいた元の状態に戻し、理由をメモする

**コピーして使うプロンプト**

```
~/.claude/skills/ と、このプロジェクトの .claude/skills/ にある SKILL.md をすべて読んでください。ファイルは書き換えないでください。次の観点で診断し、スキルごとに表にしてください。
1. 本文が500行を超えていないか（行数も書く）
2. description に「何をするか」と「いつ使うか」の両方が書かれているか
3. 同じ場面で反対のことを言っている規則の組はないか
4. CLAUDE.md やほかのスキルと重複している規則はないか
5. 「必ず」「絶対」「ALWAYS」「NEVER」などの強調が多く、理由が書かれていない規則はないか
6. 日付つきの古い手順や、自分のPC専用の絶対パスが残っていないか
7. SKILL.md から参照したファイルが、さらに別のファイルを参照していないか
各問題には、ファイル名・該当箇所・直し方の案を1行で付けてください。最後に「最初に直すべき1つ」を選び、その理由を書いてください。
```
（出典：https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices）

- **完成するもの**：スキルの診断表と、1か所を直したスキル、直す前と後の比べたメモ
- **確認方法**：診断表がスキルごとに出ていて、直した1か所について、直す前と後で同じ頼みごとを2回ずつ試した結果（スキルが使われたか・結果の良し悪し）がメモに残っている

### 重要ポイント

- **AIはMCPサーバー経由に**：Gmail・Driveなどを使うAIエージェントは、Googleが用意したMCPサーバーを通す必要がある。

- **保存は30日まで・学習禁止**：受け取った技術情報を30日より長く保存することや、AIの学習・評価用データにすることは禁止。

### 技術解説

**何が新しいのか**：これまでは普通のアプリと同じようにREST APIで自由につなげたが、AIエージェントだけは専用の窓口（MCPサーバー）を通すという区別ができた。

**従来との違い**：従来はAPIの使い方に「AIかどうか」の区別がなかった。今後はAIが動かすかどうかで、使う窓口・利用枠・データの扱いが変わる。

- MCP（Model Context Protocol）は、AIと外部の道具をつなぐ共通のつなぎ方。
- 規約では、道具の分類をごまかしてこの決まりを逃れることも禁止している。
- 公式の利用枠ページでは、Gmailのsearch_threadsとlist_draftsは1回で10回分として数えられる。
- AIを使わない定期バックアップなどは対象外と紹介記事は説明している。

## 2. Hugging Face「Swarms, Flocks, Gangs」：4体の小型AI（Qwen3-0.6B）に、メッセージで協力することを強化学習で練習させ、成功率と使う文章量の変化を公開（TRLで再現手順つき）

*最新AIニュース｜Hugging Face・公開 2026-11-26 00:00｜評価 74/100*

出典：https://huggingface.co/blog/training-swarms

**結論**：Hugging Faceは、同じ小型AIを4体のチームとして動かし、メッセージで情報を集める課題を強化学習で練習させた実験を公開しました。チームは協力が上手になり、成功率が上がる一方で使う文章の量は減りました。

> 💡 **こう使うと面白い**：自分のエージェントを「1体で全部やる」場合と「3体に分ける」場合で、同じ予算のときにどちらが良い結果を出すか比べてみると面白いです。

### 重要ポイント

- **4体のAIで数字を共有**：4体がそれぞれ1〜99の数字を1つ持ち、メッセージで送り合って全部を小さい順に並べられたら成功。
- **成功率 約7%→約82%**：練習の最初の5回と最後の5回の平均で、成功率が約6.6%から約82.3%に上がった。
- **文章量は約37%減**：1チームが使う文章の量は約1万2,800から約8,000トークンに減り、送るメッセージの数は増えた。
- **比べるときは計算量をそろえる**：記事は、AIを増やす効果は同じ量の計算で比べるべきだと強調している。

### 技術解説

**何が新しいのか**：AIのチームがうまく協力することを、チーム全体の結果だけを報酬にして練習させ、その手順をTRLの例として誰でも再現できる形で公開した。

**なぜ重要か**：AIを何体も動かすと、本当に協力が役立っているのか、ただ計算を多く使っているだけなのかが分かりにくい。記事は、AIの数も「規模」の1つとして、同じ予算で比べる考え方を示している。

**従来との違い**：リーダー役のAIだけを訓練する方式とちがい、対等な4体がお互いにメッセージを送り合う形を、同じ1つのモデルで練習させている。

- 4体は同じ1つのモデル（Qwen3-0.6B）を使い、それぞれ別の会話の記録を持つ。
- 道具は message（送る）、read_messages（読む）、check_notifications（通知を確かめる）の3つ。
- 成功したチームには、使った文章量に応じて最大25%減らした報酬を与え、失敗は0。メッセージ自体への報酬はない。
- 1つの問題につき8チームずつ挑戦させ、チーム内で同じ評価を共有して学習する。

### 実践アイデア

- 小型モデルを自分の課題向けに強化学習する練習

## 3. NVIDIA、文書の画像を構造化データに変える小型モデル Nemotron 3.5 Parse の学習データ公開、追加学習（SFT＋強化学習）の手順、高速化の工夫を解説

*最新AIニュース｜Hugging Face・公開 2026-11-26 05:05｜評価 66/100*

出典：https://huggingface.co/blog/nvidia/building-on-nemotron-35-parse-open-data-fine-tunin

**結論**：NVIDIAは、書類の画像を読み取って表やグラフまで整理されたデータに変える小型モデル Nemotron 3.5 Parse について、学習データの公開、自分の書類に合わせる追加学習の方法、速く動かす工夫をまとめました。歯科の書類の例では、追加学習で最初の1回の成功率がほぼ0%から約96%に上がったと報告しています。

> 💡 **こう使うと面白い**：紙の説明書や学校のプリントを写真に撮って読み取らせ、表もそのまま残した「自分専用の検索できるメモ帳」を作ると便利です。

### 重要ポイント

- **書類の画像を整理データに**：ページの画像から、見出し・段落・表・グラフを読む順番どおりに取り出し、位置も返す。
- **学習データを3種類公開**：グラフ・表・多言語の文字読み取り用の、合成データ3種類を公開した。
- **自分の書類向けに追加学習**：教えて覚えさせる段階と、答えを確かめて報酬を与える段階の2段階で、自分の書類に合わせられる。
- **約0.6Bの小型モデル**：モデルカードでは約6.3億パラメーター。商用・非商用どちらにも使えるとしている。

### 技術解説

**何が新しいのか**：モデルだけでなく、学習に使った合成データ（グラフ約998万件、表100万件、多言語文字約790万件）と、追加学習の手順を公開した。

**なぜ重要か**：AIに資料を読ませて答えさせる仕組み（RAG）では、最初に書類を正しく読み取れるかが結果を左右する。小型で、自分の書類向けに鍛え直せる点が大きい。

**従来との違い**：前の版（Parse 2.0）より大幅に速く、H200 1台で毎秒約20ページ（前の版は約3ページ）を処理できると報告している。強化学習の段階で、同じ文を繰り返す失敗も大きく減った。

- 画像の大きさに合わせて入力を変える方式で、決まった大きさの枠に押し込まない。
- 先読みの小さなモデル（DFlash2）が最大32トークン先まで予想し、本体がまとめて確かめて速くする。
- 表やグラフを切り出して読み直す「2回読み・3回読み」で精度を上げられる（その分遅くなる）。
- Transformers や vLLM で動かせる。

### 実践アイデア

- 紙の説明書やプリントを写真から検索できるメモに変える
- 表やグラフが多いPDFを、AIが読みやすいMarkdownに変換
