1. Google、日常のコーディングとエージェント作業向けの速いモデル「Gemini 4 Hydrogen」を発表

Google DeepMind・公開 2026-11-12 18:00
出典：https://deepmind.google/blog/introducing-gemini-4-hydrogen/

結論：Googleが新モデルGemini 4 Hydrogenを発表した。深く考える上位モデル（Carbon、Argon）に対し、Hydrogenは毎日くり返す作業を速くこなす役目。コード修正や資料のまとめ、アプリの試作などが得意だとしている。

💡 こう使うと面白い：長い説明書のPDFや表を渡して、出典つきの要点メモを作らせると、調べものがぐっと楽になります。

重要ポイント

  • 毎日の作業向けの速いモデル：Googleは「エージェント作業の毎日の相棒」と説明。小さなコード修正や調べものを速くこなす。
  • 上位モデルと手分けできる：上位モデルのCarbonが全体をまとめ、Hydrogenが作業や確認を担当する使い方も紹介された。
  • 長い資料もまとめて読める：とても長い入力を受け付け、PDF・表・音声・動画をまとめて出典つきの報告にできるとしている。
  • AI Studioやアプリで利用可：Gemini APIとGoogle AI Studio、Geminiアプリなどで提供。無料ユーザーはアプリの自動選択で使われる場合がある。

技術解説

何が新しいか
上位モデルに近い成績を、より速く安くねらう「毎日使い」の位置づけ。考える深さを4段階で選べ、新たに一番深い「xhigh」が加わった。
なぜ重要か
AIに作業を任せるとき、全部を一番高いモデルでやる必要がなくなる。速いモデルに細かい作業を任せ、難しい所だけ上位モデルに回すという分担がしやすくなる。
従来との違い
Googleによると、前の速いモデル（Gemini 3.8 Flash）より作業の成功率が大きく上がり、約2.5倍速く終わる。数値はGoogle自身の発表。
  • ファイルの読み込みや検索をまとめて並行して行い、大きなコードでも早く全体をつかむ
  • 考える深さを low / medium / high（初期値）/ xhigh から選び、質・速さ・費用を調整できる
  • 入力と出力の上限はそれぞれ最大100万トークン

実践アイデア

  • 個人開発：小さなバグ修正やコードの質問を速いモデルに任せる
  • 自動化：長いPDFや表を読ませて出典つきの要約を作る
  • エージェント：上位モデルが指示し、速いモデルが作業と確認をこなす分担

2. Google、はい・いいえ／選択／採点に特化したGemini Decisions APIを公開（モデルはGemini Decision 1）

Google・公開 2026-11-11 18:00
出典：https://blog.google/innovation-and-ai/technology/developers-tools/gemini-decisions-api/

結論：Googleが、決まった選択肢の中から判断することに特化したGemini Decisions APIを公開した。はい・いいえ、選択、採点の3種類の質問に、確率と自信の値で答える。出力の料金はかからない。

💡 こう使うと面白い：届いた問い合わせメールを「急ぎかどうか」「どの種類か」に自動で振り分け、自信が低いものだけ自分で見るようにすると、受信箱の整理が楽になります。

重要ポイント

  • 文章を書かず「判断」だけ返す：答えの文章を少しずつ作るのではなく、選択肢ごとの確からしさを一度に計算して返す。
  • 質問は3種類：はい／いいえ（noul）、選択肢から選ぶ（choice）、決めた基準で点をつける（score）の3種類。
  • 自信の度合いも数字で返る：どの答えにも0〜1の自信の値がつくので、迷ったときだけ人に回すといった仕組みが作れる。
  • 画像・音声・動画も判断：文章・画像・音声・動画・PDFをまとめて1回で判断できる。1回で最大1,000問まで聞ける。

技術解説

何が新しいか
文章を作らず、選択肢の確からしさを1回の計算で返す「判断専用」のモデル。画像・音声・動画・PDFもそのまま判断材料にできる。
なぜ重要か
エージェントの中では「どの道具を使うか」「ルール違反か」など、小さな判断が何度も出てくる。これを安く速く、自信の値つきで任せられるので、迷う場面だけ人や大きなモデルに回せる。
従来との違い
ふつうのチャット型AIに選ばせる場合と比べ、答えが決まった形で返り、自信の度合いも数字で分かる。Googleは、同社の軽量モデルより約5分の1の費用だとしている。
  • 質問ごとに noul（はい／いいえ）、choice（2〜255個の選択肢）、score（0から始まる段階の採点）を指定する
  • 共通の入力（画像や文章）は1回分だけ課金され、質問が増えても追加は質問文の分だけ
  • Pythonでは google-genai SDK（3.2以降）の v1beta から呼び出す

実践アイデア

  • 自動化：問い合わせメールを「急ぎ？」「どの種類？」で振り分ける
  • エージェント：次に使う道具を選ぶ判断だけをこのAPIに任せる
  • 画像・動画：投稿された画像がルールに合っているかを、自信の値つきで判定する

3. Claude Code v2.1.323：権限チェックやサンドボックスの穴を多数修正、試験的なCode Modeを追加、未知のモデルは1M扱いに

Anthropic・公開 2026-11-12 22:12
出典：https://github.com/anthropics/claude-code/releases/tag/v2.1.323

結論：Claude Code v2.1.323は、Bashの権限チェックやサンドボックスを回避できた穴を多数ふさいだ大きめの更新。試験的なCode Modeや、プラグインの対応バージョン宣言も加わった。

重要ポイント

  • 権限チェックの穴を多数修正：許可ルールをすり抜けて確認なしでコマンドが動くケースや、サンドボックスが途中で切れるケースなどが直った。
  • 試験的なCode Modeが登場：Claudeが道具を呼ぶためにJavaScriptを書く、オプトイン（自分で有効にする）の試験機能。
  • 未知のモデルは1M扱いに：名前を知らないモデルの「一度に覚えておける量」を200Kから1Mとみなすように変更。小さいモデルでは設定で戻せる。
  • 古いMCPクライアントを削除：MCP v1クライアントが削除され、MCP_SDK_GENERATION=v1 はv2の互換モードで動くようになった。

技術解説

何が新しいか
Code Mode（試験的・オプトイン）、plugin.jsonの engines["claude-code"]、`*` を含む許可ルールへの起動時警告などが追加された。
なぜ重要か
AIに作業を任せるほど「許可した範囲だけで動く」ことが大事になる。今回はその土台の穴が多く直ったので、自分で許可ルールを書いている人ほど更新の意味が大きい。
従来との違い
これまで確認なしで通っていた一部のコマンドで、確認を求められるようになる。auto モードが使えないときは、より安全な手動モードで始まるようになった。
  • Bash(ls*) のように後ろに * がつく許可ルールが、一部で確認を飛ばしていた問題を修正
  • sudo や env などで包んだコマンドが deny/ask ルールをすり抜けるケースを修正
  • Read の deny ルールがかかったパスに、Write/Edit で書けてしまうケースを修正
  • 未知のモデルIDの想定量を1Mに変更。小さいモデルでは CLAUDE_CODE_DISABLE_1M_CONTEXT=1 で200Kのまま

実践アイデア

  • 自動化：毎朝動かしている claude -p の処理で、許可ルールの警告が出ていないか確認する
  • 個人開発：Bashの許可ルールに * を使っている所を見直す

4. GitHub Blog：エージェントスキルの実践ガイド。手順はファイルで共有し、道具や権限は実行する側が用意する

GitHub・公開 2026-11-12 22:54
出典：https://github.blog/ai-and-ml/github-copilot/build-once-run-on-any-agent-a-practical-guide-to-agent-skills/

結論：GitHubブログが、くり返す仕事の手順を「スキル」としてファイルにまとめ、いろいろなAIエージェントで使い回す方法を解説した。手順は共有できても、道具・認証・権限はそれを動かす環境が用意する、という線引きが要点。

💡 こう使うと面白い：公開前のチェック手順をスキルにして .claude/skills に置けば、Claude CodeでもCopilotでも同じ確認を呼び出せます。

重要ポイント

  • 手順を1つのファイルに書く：スキルはSKILL.mdを中心にしたフォルダ。いつ・どう作業するかを書いておく。
  • いろいろなAIで使い回せる：同じスキルから、Claude Code・Cursor・Copilot向けのファイルを作り分ける例が紹介された。
  • スキルは権限を与えない：スキルは「やり方」を教えるだけ。データベースなどへのアクセスは実行する環境が用意する。
  • 自分の仕事は別のAIが確認：AIに自分の仕事を採点させず、別の確認役が元の依頼と変更点だけを見て判定する例（Proof Agent）。

技術解説

何が新しいか
1つのスキルから各エージェント用のファイルを作り分ける実例と、確認役を分ける「Proof Agent」、複数スキルでデータ処理を進める「Data Forge」という具体的なデモが公開された。
なぜ重要か
同じ手順をAIごとに書き直す手間がなくなる。また「スキルは権限を与えない」という整理は、AIに任せる範囲を安全に決めるうえで役に立つ。
従来との違い
長い指示を毎回プロンプトに貼る代わりに、手順をファイルで管理し、レビューやバージョン管理ができる。
  • SKILL.md の先頭に name と description を書き、本文に手順を書く
  • Copilotはリポジトリの .github/skills・.claude/skills・.agents/skills からスキルを読む
  • Claude Codeは .claude/skills/<名前>/SKILL.md を読み、/名前 で呼び出せる
  • 共通の情報（名前や表の構成）は1つの設定ファイルにまとめ、各スキルはそれを読む

実践アイデア

  • 個人開発：公開前チェックの手順をスキルにして毎回同じ確認をさせる
  • エージェント：作る役と確かめる役を別のスキルに分ける
  • 自動化：記事やリリースノートの下書き手順をスキルにして使い回す

5. Zenn：Claude Codeのauto memoryを見返させて整理したら、MEMORY.mdが146行→122行になり、終わった予約を答えに出さなくなった

Zenn・公開 2026-11-12 22:02
出典：https://zenn.dev/zundamon_tools/articles/claude-code-auto-memory-review

結論：Claude Codeのauto memoryの目次（MEMORY.md）を見直し用コマンドで整理させ、整理前と後で答えを比べた記事。整理後は終わった予約を答えに持ち出さなくなった。

💡 こう使うと面白い：週に一度、記憶の見直しコマンドを走らせて、終わった予定や片付いた作業を記憶から片付ける習慣にすると、答えがすっきりします。

重要ポイント

  • 記憶は書きっぱなしになりがち：Claude Codeは覚えたことをMEMORY.mdという目次に書き足すが、人が見直さないと古い行が残る。
  • 古い予定が答えに混ざった：公開日を過ぎた予約が目次に残っていて、質問すると2回とも答えに含めた。
  • 整理で146行→122行に：見直し用のコマンドで1回整理させると行数とサイズが減り、入力の量も約2割減った。
  • 消さずに別ファイルへ移す：終わった予約は削除せず、目次から1行でリンクした別の索引ファイルに移された。

技術解説

何が新しいか
auto memoryを「書いたら終わり」にせず、定期的にAI自身に見返させる手順と、その前後の比較結果を示した。
なぜ重要か
MEMORY.mdは毎回の会話の最初に読み込まれ、先頭の200行か25KBまでしか読まれない。古い行が残ると、答えが古い情報に引っぱられたり、大事な行が読まれなくなったりする。
従来との違い
CLAUDE.mdは人が書く指示、auto memoryはClaudeが自分で書くメモ。後者は人が見ないまま増えるので、見直しの仕組みが別に必要になる。
  • auto memoryは ~/.claude/projects/<project>/memory/ に保存され、MEMORY.mdが目次、個別のメモは必要なときだけ読まれる
  • MEMORY.mdは先頭200行または25KBまでが毎回読み込まれる
  • /memory からauto memoryのフォルダを開いて、直接読んだり直したりできる
  • 記事の検証は1つの記憶・1モデル・各2回という小さな試し

実践アイデア

  • 自動化：週1回、記憶の見直しを実行する習慣にする
  • エージェント：長く動かすエージェントの記憶を、終わった用事と今の方針に分けて整理する

6. Diffusers 0.43.0：MiniMax-H3-Image、Pika H3 Flex、P-H3-Image、Kandinsky S2V、PAN 2の5つのモデルに対応

Hugging Face・公開 2026-11-12 06:38
出典：https://github.com/huggingface/diffusers/releases/tag/v0.43.0

結論：画像・動画生成のライブラリDiffusersの0.43.0が公開され、画像の生成と編集、音つき動画、話す人の動画、世界シミュレーションの5つのモデルが加わった。注意の計算方式やLoRAの扱いなども改善された。

重要ポイント

  • 画像の生成と編集：MiniMax-H3-ImageとP-H3-Imageは、文章から画像を作り、参考画像を使った編集もできる。
  • 音つき動画の生成：Pika H3 Flexは、ステレオ音声と合った動画を6ステップで作る。最初や最後のコマを指定できる。
  • 写真と声から話す動画：Kandinsky S2Vは、人の写真と話し声から、声に合わせて全身が動く動画を5秒ずつ作る。
  • 動きを予想する世界シミュレーション：PAN 2は、動きやカメラの指示から場面の変化を作る。安全チェックが初期状態で有効。

技術解説

何が新しいか
5つの新モデルが「部品を組み合わせる」形式（モジュラーパイプライン）で使えるようになった。AMDのGPU向けの高速化も追加。
なぜ重要か
いろいろな会社の新しい生成モデルを、同じPythonの書き方で試せる。画像・動画・音を組み合わせた制作の選択肢が広がる。
従来との違い
これまで個別のコードが必要だった新モデルを、Diffusersの共通の読み込み方（ModularPipeline.from_pretrained と load_components）で扱える。
  • MiniMax-H3-Imageは6ステップの固定スケジュールと、短い指示を詳しく書き直すプロンプト補強の仕組みを持つ
  • Kandinsky S2Vは5秒ごとに動画を作り、前の区切りの記憶を引き継ぐ。音声はそのまま音として使う
  • PAN 2は290億パラメータの大きなモデルで、安全チェックに別パッケージ pan2-guardrail が必要
  • torch 2.6以上・transformers 4.41.2以上の最低バージョンが強制されるようになった

実践アイデア

  • 画像・動画：参考画像を使って、キャラクターの絵を同じ雰囲気でそろえる
  • 音楽：自分の曲に合わせた短い動画を作る
  • 動画：写真と声からナレーション動画を作る
