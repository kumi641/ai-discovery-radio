## 今日の実験

関連ニュース：Zenn：Claude Codeのauto memoryを見返させて整理したら、MEMORY.mdが146行→122行になり、終わった予約を答えに出さなくなった

#### 実験：Claude Codeの記憶の大そうじ

- **目的**：auto memory の目次（MEMORY.md）を、終わった用事を消さずに移しながら短く整理し、答えが古い情報に引っぱられないようにする
- **使用ツール**：Claude Code
- **必要な準備**：しばらく使っていて auto memory がたまっている Claude Code のプロジェクト、念のため、auto memory のフォルダ（~/.claude/projects/<project>/memory/）をどこかにコピーしておく
- **所要時間**：約20分
- **費用**：Claude Codeの利用プランの範囲内（追加の費用なし）
- **無料の代替**：Claude Codeを使わない場合でも、/memory で開いたファイルを手で見直す方法は同じ考え方で使える

**手順**

1. Claude Codeで /memory と打ち、auto memory のフォルダを開いて MEMORY.md の行数と、終わった用事の行を確認する
2. 整理する前に、終わった用事に関係する質問（例：「まだ終わっていない予定は？」）を1つして、答えをメモする
3. ~/.claude/skills/memory-review/SKILL.md を作り、下の内容を貼り付ける
4. Claude Codeで /memory-review と打って実行する。編集の確認が出たら、中身を読んでから許可する
5. 報告された変更前後の行数を確かめ、移した行が archive_index.md にあり、MEMORY.md から1行でたどれるか確認する
6. 新しい会話を始めて、手順2と同じ質問をし、終わった用事が答えに出なくなったか比べる

**コピーして使うコマンド**

```
---
name: memory-review
description: auto memory の MEMORY.md を見直して整理する（週1回の見直し用）
disable-model-invocation: true
---

auto memory のフォルダを見直して整理してください。

- MEMORY.md は1行1件の短い索引にする
- 重複したメモはまとめる
- 終わった予定・片付いた作業は削除せず archive_index.md に移し、MEMORY.md から1行でリンクする
- 今の方針と食い違うメモは、どちらを残すか私に確認する
- 最後に、変更前と変更後の MEMORY.md の行数と、移した行の一覧を報告する

```
（出典：https://code.claude.com/docs/en/skills）

- **完成するもの**：短く整理された MEMORY.md と、終わった用事をまとめた archive_index.md
- **確認方法**：MEMORY.md の行数が減り、移した行が archive_index.md からたどれ、整理後の質問で終わった用事が答えに出てこない
- 参考：https://code.claude.com/docs/en/skills

## 1. Google、日常のコーディングとエージェント作業向けの速いモデル「Gemini 4 Hydrogen」を発表

*最新AIニュース｜Google DeepMind・公開 2026-11-12 18:00｜評価 82/100*

出典：https://deepmind.google/blog/introducing-gemini-4-hydrogen/

**結論**：Googleが新モデルGemini 4 Hydrogenを発表した。深く考える上位モデル（Carbon、Argon）に対し、Hydrogenは毎日くり返す作業を速くこなす役目。コード修正や資料のまとめ、アプリの試作などが得意だとしている。

> 💡 **こう使うと面白い**：長い説明書のPDFや表を渡して、出典つきの要点メモを作らせると、調べものがぐっと楽になります。

### 重要ポイント

- **毎日の作業向けの速いモデル**：Googleは「エージェント作業の毎日の相棒」と説明。小さなコード修正や調べものを速くこなす。
- **上位モデルと手分けできる**：上位モデルのCarbonが全体をまとめ、Hydrogenが作業や確認を担当する使い方も紹介された。
- **長い資料もまとめて読める**：とても長い入力を受け付け、PDF・表・音声・動画をまとめて出典つきの報告にできるとしている。
- **AI Studioやアプリで利用可**：Gemini APIとGoogle AI Studio、Geminiアプリなどで提供。無料ユーザーはアプリの自動選択で使われる場合がある。

### 技術解説

**何が新しいのか**：上位モデルに近い成績を、より速く安くねらう「毎日使い」の位置づけ。考える深さを4段階で選べ、新たに一番深い「xhigh」が加わった。

**なぜ重要か**：AIに作業を任せるとき、全部を一番高いモデルでやる必要がなくなる。速いモデルに細かい作業を任せ、難しい所だけ上位モデルに回すという分担がしやすくなる。

**従来との違い**：Googleによると、前の速いモデル（Gemini 3.8 Flash）より作業の成功率が大きく上がり、約2.5倍速く終わる。数値はGoogle自身の発表。

- ファイルの読み込みや検索をまとめて並行して行い、大きなコードでも早く全体をつかむ
- 考える深さを low / medium / high（初期値）/ xhigh から選び、質・速さ・費用を調整できる
- 入力と出力の上限はそれぞれ最大100万トークン

### 実践アイデア

- 個人開発：小さなバグ修正やコードの質問を速いモデルに任せる

- エージェント：上位モデルが指示し、速いモデルが作業と確認をこなす分担

## 2. Google、はい・いいえ／選択／採点に特化したGemini Decisions APIを公開（モデルはGemini Decision 1）

*最新AIニュース｜Google・公開 2026-11-11 18:00｜評価 90/100*

出典：https://blog.google/innovation-and-ai/technology/developers-tools/gemini-decisions-api/

**結論**：Googleが、決まった選択肢の中から判断することに特化したGemini Decisions APIを公開した。はい・いいえ、選択、採点の3種類の質問に、確率と自信の値で答える。出力の料金はかからない。

> 💡 **こう使うと面白い**：届いた問い合わせメールを「急ぎかどうか」「どの種類か」に自動で振り分け、自信が低いものだけ自分で見るようにすると、受信箱の整理が楽になります。

### 重要ポイント

- **文章を書かず「判断」だけ返す**：答えの文章を少しずつ作るのではなく、選択肢ごとの確からしさを一度に計算して返す。
- **質問は3種類**：はい／いいえ（noul）、選択肢から選ぶ（choice）、決めた基準で点をつける（score）の3種類。
- **自信の度合いも数字で返る**：どの答えにも0〜1の自信の値がつくので、迷ったときだけ人に回すといった仕組みが作れる。
- **画像・音声・動画も判断**：文章・画像・音声・動画・PDFをまとめて1回で判断できる。1回で最大1,000問まで聞ける。

### 技術解説

**何が新しいのか**：文章を作らず、選択肢の確からしさを1回の計算で返す「判断専用」のモデル。画像・音声・動画・PDFもそのまま判断材料にできる。

**なぜ重要か**：エージェントの中では「どの道具を使うか」「ルール違反か」など、小さな判断が何度も出てくる。これを安く速く、自信の値つきで任せられるので、迷う場面だけ人や大きなモデルに回せる。

**従来との違い**：ふつうのチャット型AIに選ばせる場合と比べ、答えが決まった形で返り、自信の度合いも数字で分かる。Googleは、同社の軽量モデルより約5分の1の費用だとしている。

- 質問ごとに noul（はい／いいえ）、choice（2〜255個の選択肢）、score（0から始まる段階の採点）を指定する
- 共通の入力（画像や文章）は1回分だけ課金され、質問が増えても追加は質問文の分だけ
- Pythonでは google-genai SDK（3.2以降）の v1beta から呼び出す

### 実践アイデア

- 自動化：問い合わせメールを「急ぎ？」「どの種類？」で振り分ける
- エージェント：次に使う道具を選ぶ判断だけをこのAPIに任せる
- 画像・動画：投稿された画像がルールに合っているかを、自信の値つきで判定する

## 4. GitHub Blog：エージェントスキルの実践ガイド。手順はファイルで共有し、道具や権限は実行する側が用意する

*エンジニアの実践ノウハウ｜GitHub・公開 2026-11-12 22:54｜評価 86/100*

出典：https://github.blog/ai-and-ml/github-copilot/build-once-run-on-any-agent-a-practical-guide-to-agent-skills/

**結論**：GitHubブログが、くり返す仕事の手順を「スキル」としてファイルにまとめ、いろいろなAIエージェントで使い回す方法を解説した。手順は共有できても、道具・認証・権限はそれを動かす環境が用意する、という線引きが要点。

> 💡 **こう使うと面白い**：公開前のチェック手順をスキルにして .claude/skills に置けば、Claude CodeでもCopilotでも同じ確認を呼び出せます。

### 重要ポイント

- **手順を1つのファイルに書く**：スキルはSKILL.mdを中心にしたフォルダ。いつ・どう作業するかを書いておく。
- **いろいろなAIで使い回せる**：同じスキルから、Claude Code・Cursor・Copilot向けのファイルを作り分ける例が紹介された。
- **スキルは権限を与えない**：スキルは「やり方」を教えるだけ。データベースなどへのアクセスは実行する環境が用意する。
- **自分の仕事は別のAIが確認**：AIに自分の仕事を採点させず、別の確認役が元の依頼と変更点だけを見て判定する例（Proof Agent）。

### 技術解説

**何が新しいのか**：1つのスキルから各エージェント用のファイルを作り分ける実例と、確認役を分ける「Proof Agent」、複数スキルでデータ処理を進める「Data Forge」という具体的なデモが公開された。

**なぜ重要か**：同じ手順をAIごとに書き直す手間がなくなる。また「スキルは権限を与えない」という整理は、AIに任せる範囲を安全に決めるうえで役に立つ。

**従来との違い**：長い指示を毎回プロンプトに貼る代わりに、手順をファイルで管理し、レビューやバージョン管理ができる。

- SKILL.md の先頭に name と description を書き、本文に手順を書く
- Copilotはリポジトリの .github/skills・.claude/skills・.agents/skills からスキルを読む
