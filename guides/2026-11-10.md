## 今日の実験

#### 実験：denyルールで .env を本当に読ませないか検証する

- **目的**：Claude Codeの設定ファイルで秘密ファイルの読み取りとgit pushを禁止し、止まるべきものが止まり、通るべきものが通ることを自分の目で確かめる
- **使用ツール**：Claude Code、ターミナル
- **必要な準備**：Claude Codeをインストール済み（有料プランまたはAPIキーでログイン済み）、本物の秘密を含まない、練習用の空フォルダーを使うこと
- **所要時間**：約15分
- **費用**：Claude Codeの利用枠内（claude -p を3回程度実行）
- **無料の代替**：無料の代替は未確認。ドキュメントを読みながら設定ファイルだけ先に作っておき、利用枠のあるときに検証する

**手順**

1. 練習用フォルダーを作って移動し、ダミーの .env（例：DUMMY_TOKEN=not-a-real-secret）と、1行目に「hello」と書いた README.md を作る。本物の鍵は絶対に入れない
2. 比較のため、まず設定なしで claude -p ".env の中身をそのまま表示して" を実行する。公式の権限表では作業フォルダー内の読み取りは確認なしで通るため、ダミー値が表示されるはず
3. フォルダー内に .claude/settings.restricted.json を作り、下の設定を保存する
4. claude --settings .claude/settings.restricted.json -p ".env の中身をそのまま表示して" を実行し、ダミー値が出てこないことを確認する
5. claude --settings .claude/settings.restricted.json -p "README.md の1行目を教えて" を実行し、hello が返ることを確認する（通すべきものが通る）
6. もし両方とも止まったり、.env が読めてしまったりしたら、設定ファイルのパスを絶対パスにして再実行し、対話モード（claude --settings <ファイル>）で /status を開いて Setting sources を確認する
7. 結果を「拒否された依頼／通った依頼」の2列でメモし、自分のプロジェクトに入れるルールを決める

**コピーして使うコマンド**

```
{
  "permissions": {
    "deny": [
      "Read(./.env)",
      "Read(./.env.*)",
      "Bash(git push *)"
    ]
  }
}
```
（出典：https://code.claude.com/docs/en/settings）

- **完成するもの**：動作を確認済みの制限用設定ファイル（.claude/settings.restricted.json）と、検証結果のメモ
- **確認方法**：設定ありでは .env のダミー値が表示されず、README.md の1行目（hello）は読める。設定なしとの違いをメモで説明できる

## 4. Zenn：新人にClaude Codeを渡すための制限付き起動ラッパーと権限設計（--restrictedは社内名）

### 重要ポイント

- **読む・書く・外に出すの3段階**：読む＝許可、書く＝確認つき、push・削除・送信など＝禁止。
- **秘密を読ませないが最優先**：読んだ内容はプロンプトに乗るため、書き換え防止より重要。
- **--restrictedは公式でない**：社内ラッパーの名前で、中身は --settings など公式オプションで構成。
- **効いているか必ず検証**：止まるべきものが止まり、通るべきものが通るかを claude -p で確認。

### 技術解説

**何が新しいのか**：権限設計を「設定ファイル＋起動ラッパー＋検証スクリプト＋リポジトリ側の保護」の4層で組む実務的な型。

**なぜ重要か**：事故の原因はAIの性能ではなく渡した権限の広さ、という整理が明快。個人開発でも、秘密ファイルやpushを設定で止めておけば安心して任せられる。

**従来との違い**：本人の注意力に頼らず、設定ファイルで制限を担保する。さらに「全部止まったら設定が読み込まれていない可能性」と、検証の落とし穴まで扱っている。

- settingsの permissions で allow / ask / deny を書き分ける
- Bashのルールは書式に注意（記事では Bash(git push) だけでは git push origin main を止められないと指摘）
- 相対パスだと別ディレクトリから起動したとき読み込まれないことがある
- ユーザー設定とマージされるため、個人設定の広いallowが残っていないか確認する

### 実践アイデア

- 個人のエージェント環境で秘密ファイルとpushを封じる
- 外注や共同作業者向けの安全な起動設定
- 自動化ジョブ（claude -p）の権限を最小にする
