実験：MCPの鍵を環境変数へ移す

目的
MCP サーバーの鍵をファイルから追い出し、ファイルには ${変数名} だけが残る安全な形に直す
使用ツール
Claude Code、ターミナル
必要な準備
Claude Code が入ったパソコン、鍵（トークン）を使う HTTP の MCP サーバーを登録したプロジェクト（無ければダミーのサーバー名とダミーの鍵で練習）
所要時間
約25分
費用
無料（Claude Code 自体の料金は未確認、公式の料金ページで確認）
無料の代替
Claude Code が無い場合も、grep による確認と、設定ファイルを変数の形に書き換える練習はできる
手順
  1. 練習用ならプロジェクトを git に入れる前の場所で行う。quick_try の grep を実行し、鍵の直書きがあるファイルと行番号を確かめる
  2. 鍵が .mcp.json にある場合は、そのサーバーの headers を下の設定例の形に書き換える。変数名は ANTHROPIC_API_KEY などの Claude Code 用の名前を避け、サーバー専用の名前（例：MY_SERVER_KEY）にする
  3. 鍵が ~/.claude.json にある場合（local や user で登録したもの）は、手で編集せず、claude mcp remove でいったん消し、プロジェクトの .mcp.json に変数の形で書き直す
  4. 本当の鍵の値は、ターミナルの環境変数（例：シェルの設定で export する）に置き、Claude Code をその環境から起動し直す
  5. claude mcp list を実行し、そのサーバーに「変数が足りない」警告が出ていないことを確かめる
  6. もう一度 grep を実行し、さっきの行が出なくなったことを確かめる
  7. 鍵が一度でもコミットや push されていた場合は、ファイルを直すだけでは履歴に残るので、サービス側で鍵を無効にして作り直す
コピーして使うコマンド
{
  "mcpServers": {
    "api-server": {
      "type": "http",
      "url": "${API_BASE_URL:-https://api.example.com}/mcp",
      "headers": {
        "Authorization": "Bearer ${API_KEY}"
      }
    }
  }
}
出典：https://code.claude.com/docs/en/mcp
完成するもの
鍵の値が入っていない .mcp.json と、環境変数から鍵を読んで動く MCP サーバーの設定
確認方法
grep で鍵の直書きが出ず、claude mcp list でそのサーバーに変数が足りない警告が出ていなければ成功。Claude Code からそのサーバーの道具が使えれば、鍵がきちんと渡っている
参考：https://code.claude.com/docs/en/mcp　https://qiita.com/supportapp3/items/b73c21efacc605616bf9

1. Simon Willison、datasette-charts 0.2a0 を公開。Datasette Agent に「グラフにして」と頼むと、チャットの中にグラフを作る

Simon Willison・公開 2026-11-24 04:24
出典：https://simonwillison.net/2026/Nov/24/datasette-charts/

結論：データをためておく道具 Datasette 用のグラフ機能 datasette-charts が、0.2a0 で AI のチャット機能 Datasette Agent とつながりました。チャットで「このデータの変化をグラフにして」と頼むと、グラフの候補を選ぶ仕組みと同じ道具を使って、チャットの中にグラフを作ります。前日に公開された最初の版は、作者が Claude Fable 5.2 で試作したものだと書いています。

💡 こう使うと面白い：自分のブログやアプリのアクセス数を SQLite にためておき、AI に「先月いちばん伸びた日をグラフで見せて」と話しかけるだけで、ふり返りのグラフを作ると面白そうです。

重要ポイント

  • チャットで頼むとグラフを作成：Datasette Agent に頼むと、グラフ用の道具を使って、チャットの中にグラフを表示する。
  • #で表を探して指定できる：チャットで「#stats」のように打つと、表を探す欄が開き、使うデータを選べる。
  • 横の画面で直すとAIも把握：「チャートビルダーで開く」で横の画面に出し、そこで変えたグラフについてAIに聞くと、変えた後の内容を説明した。
  • 公開デモで試せる：agent.datasette.io でギットハブのアカウントを使ってログインすると試せる。

技術解説

何が新しいか
グラフ機能を AI エージェントからも使えるようになり、言葉で頼むだけでグラフが出るようになった。横の画面でグラフを変えると、AI がその変化を知った上で答える。
なぜ重要か
これまではグラフの種類や軸を自分で選ぶ必要があった。AI に「何を見たいか」を言うだけで、データに合ったグラフが出てくるので、データを見る手間が大きく減る。
従来との違い
AI が自由にグラフのコードを書くのではなく、もともと用意されたグラフの候補選びと作成の道具を、AI が呼び出して使う形になっている。
  • グラフは毎回 SQL の集計（グループごとの合計や時間ごとのまとめ）に変換され、表示中の1ページではなく全部の行を使う（結果は最大5,000行）。
  • グラフの状態は URL の # 以降に保存されるので、ブックマークや共有ができる。
  • D3、Observable Plot、topojson-client をプラグインの中に同梱している。
  • AI は人が使うのと同じグラフの道具を使うので、結果をあとから人が画面で直せる。

実践アイデア

  • 個人開発：自分のアプリのログや売り上げを SQLite に入れて、AI に「先週との違いをグラフで」と頼む
  • エージェント：自作エージェントにも「決まったグラフ道具を呼ぶ」形を取り入れ、AI に自由なコードを書かせない
  • 自動化：毎週の数字をグラフにして URL で共有する

3. Qiita：claude mcp add --header の鍵は画面では伏せ字でも、.mcp.json や ~/.claude.json に平文で保存される。grep 1行で洗い出す方法

Qiita・公開 2026-11-24 20:20
出典：https://qiita.com/supportapp3/items/b73c21efacc605616bf9

結論：Claude Code で MCP サーバーを登録するとき、--header で入れた鍵は画面では伏せ字になりますが、保存されたファイルには平文で書かれていることを、筆者が Claude Code 2.1.330 で確認しました。保存先は登録の範囲（スコープ）で変わり、プロジェクトの .mcp.json だけでなく、ホームの ~/.claude.json にも入ります。記事は、値を表示せずに場所だけを探す grep と、環境変数を使う対策をまとめています。

💡 こう使うと面白い：週に一度、記事の grep を実行して、鍵の直書きが増えていないかを確かめる習慣をつけると、うっかり公開する事故を防げて安心です。

重要ポイント

  • 画面は伏せ字、保存は平文：--header で登録した鍵は、画面では [REDACTED] と伏せられるが、.mcp.json には平文で書かれていた。
  • 保存先は登録の範囲で変わる：project は .mcp.json、既定の local と user は ~/.claude.json に保存される。.mcp.json だけ見ても見つからない。
  • grep 1行で洗い出せる：値は表示せず、ファイル名と行番号だけを出す grep で、鍵の直書きを探せる。
  • 鍵は環境変数で参照する：公式ドキュメントのとおり ${API_KEY} の形で書けば、本当の値は環境変数に置ける。

技術解説

何が新しいか
「画面で伏せ字だから安全」と思いがちな点について、実際の保存先と中身を範囲ごとに確かめ、確認用のコマンドまで示した。
なぜ重要か
MCP は AI に外部の道具をつなぐ仕組みで、その鍵が漏れると他人に使われてしまう。.mcp.json はチームで共有するためにコミットされやすく、ホームのファイルもバックアップや AI に読ませることで外に出るおそれがある。
従来との違い
鍵をファイルに直接書く方法から、ファイルには ${API_KEY} のような「名前」だけを書き、本当の値は環境変数に置く方法に変える。
  • 公式ドキュメントによると、保存先は local と user が ~/.claude.json、project がプロジェクト直下の .mcp.json。
  • 公式ドキュメントによると、.mcp.json の command・args・env・url・headers の中で ${VAR} や ${VAR:-default} が使える。
  • リモートのサーバーの url と headers では、ANTHROPIC_API_KEY など Claude Code やクラウドの認証用の変数は、設定していても空として読まれる（鍵を外のサーバーに送らないため）。サーバー用の鍵は別の名前にする。
  • 変数が設定されていないと、claude mcp list に警告が出て、${VAR} がそのままの文字で使われる。
  • すでにコミットや push をした鍵は履歴に残るので、ファイルを直すだけでなく、鍵を無効にして作り直す。

実践アイデア

  • エージェント：自作の MCP サーバーを人に配るとき、設定例を ${変数名} の形で書く
  • 自動化：コミット前に鍵の直書きを grep で探す確認を入れる
  • 個人開発：ホームフォルダをバックアップする前に、鍵が入ったファイルを見直す
