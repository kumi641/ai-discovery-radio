#### 実験：git push を止めて、理由と代わりの手順を返すフック

- **目的**：Claude Code が勝手に git push しないよう、PreToolUse フックで止め、止めた理由と代わりにしてほしいことを Claude に伝える
- **使用ツール**：Claude Code、bash、jq
- **必要な準備**：Claude Code が使える環境（macOS / Linux）、jq をインストールしておく（公式の例が jq を使うため）、試しに使える git リポジトリ（push しても困らないもの）
- **所要時間**：約15分
- **費用**：無料（Claude Code の利用料金のみ）

**手順**

1. リポジトリに .claude/hooks フォルダを作り、下の前半を block-push.sh として保存し、chmod +x で実行できるようにする
2. 下の後半を .claude/settings.json に書く（すでにあるときは hooks の部分だけ足す）
3. 手で試す：echo '{"tool_name":"Bash","tool_input":{"command":"git push"}}' | .claude/hooks/block-push.sh; echo $? を実行し、2 が表示されることを確認する
4. Claude Code をそのフォルダで起動し、「今の変更を git push して」と頼む
5. 止まって理由の文が出ること、Claude が代わりに差分の要約とコミットメッセージ案を出すことを確認する
6. 「git status を見せて」と頼み、ほかのコマンドはいつも通り動くことを確認する

**コピーして使うコマンド**

```
#!/bin/bash
# .claude/hooks/block-push.sh
# 公式ドキュメントの「exit 2 で止める」例を、git push 用に書き換えたもの
input=$(cat)
command=$(jq -r '.tool_input.command' <<<"$input")

if [[ "$command" == *"git push"* ]]; then
  echo "Blocked: git push は人が自分で打つルールです。代わりに、変更の要約とコミットメッセージ案を見せてください。" >&2
  exit 2
fi

exit 0

# ===== ここから下は .claude/settings.json に書く内容 =====
# {
#   "hooks": {
#     "PreToolUse": [
#       {
#         "matcher": "Bash",
#         "hooks": [
#           {
#             "type": "command",
#             "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/block-push.sh"
#           }
#         ]
#       }
#     ]
#   }
# }
```
（出典：https://code.claude.com/docs/en/hooks）

- **完成するもの**：git push だけを止め、理由と代わりの手順を Claude に返すフック
- **確認方法**：手で試したときに終了コード 2 が出て、Claude Code に push を頼むと止められ、理由の文が表示される。git status など他のコマンドは普通に動く
- 参考：https://code.claude.com/docs/en/hooks

## 1. Claude Code v2.1.330：頼むとグラフを描く内蔵mod「easel」、定期タスクと/loopが最長30日に、危険なrmは承認が必要に

出典：https://github.com/anthropics/claude-code/releases/tag/v2.1.330

**従来との違い**：これまではグラフを作るには別のツールに数値を移す必要があり、定期タスクは最長7日で終わっていました。

- easel は組み込みの mod（追加機能）として提供され、自動グラフは /config で切れる

## 2. Google、Gemini API（Interactions API）に Tool Retrieval をプレビュー公開。ツールの定義を必要なときだけ読み込む

*最新AIニュース｜Google・公開 2026-11-19 18:00｜評価 86/100*

出典：https://blog.google/innovation-and-ai/technology/developers-tools/gemini-api-tool-retrieval/

**結論**：Google は Gemini API の Interactions API に、Tool Retrieval をプレビューで追加しました。たくさんの道具（AIが呼び出せる機能）を持つエージェントでも、道具の詳しい定義を毎回すべて送らずにすみます。入力の量を減らし、道具選びの正確さを保つのが目的です。

> 💡 **こう使うと面白い**：メールや予定表、メモ帳など道具が何十個もある自分専用アシスタントでも、必要な道具だけ呼び出して軽く動かせそうで面白いですね。

### 重要ポイント

- **道具の説明書を必要な分だけ**：使わない道具は名前と短い説明だけを渡し、必要になった道具の詳しい定義だけを読み込む
- **探すのはGoogle側**：tool_search を足し、道具に defer_loading を付けるだけ。検索の仕組みを自分で作らなくてよい（自前の検索も可能）
- **追加料金なし**：別料金はなく、通常のトークン料金。ただし道具が少ないと普通に渡す方が安いこともある

### 技術解説

**何が新しいのか**：tool_search という道具を追加し、関数に defer_loading を付けると、モデルには名前と説明だけが見え、必要になったときに定義が読み込まれて同じリクエスト内で呼び出されます。リモートの MCP サーバーにも使えます。

**なぜ重要か**：道具が増えるほど、毎回送る定義が長くなり、費用も迷いも増えていました。必要な分だけ読む形にすると、道具を増やしてもエージェントが重くなりにくくなります。

**従来との違い**：従来は全ての道具の定義をリクエストの最初に並べる必要がありました。今回は定義を後から読み込み、プロンプトの先頭が変わらないためキャッシュも効きやすいとされています。

- 実行の記録には tool_search_call、tool_search_result、function_call の3段階が残り、道具の名前や説明の調整に使える
- 検索はサーバー側で動く。自前の索引や権限フィルターを使いたい場合は、クライアント側で検索する方式も選べる（往復が1回増える）
- よく使う道具は defer_loading を付けずに常に読み込んでおける
- ドキュメントでは v1beta の API が必要で、プレビュー中は仕様が変わる可能性があるとしている

### 実践アイデア

- エージェント：メール・予定表・メモなど多数の道具を持つ個人アシスタントを軽く動かす
- MCP：たくさんの道具を持つ MCP サーバーを必要なときだけ読み込む
- 個人開発：道具の名前と説明の書き方を、検索の記録を見ながら改善する

**従来との違い**：従来の汎用モデルは、特定のハーネスや作業向けには最適化されていませんでした。今回はハーネスと課題を決めて、その中で直接学習しています。

- LoRA を全ての線形層に付け、TRL の AsyncGRPOTrainer による GRPO で学習
- 報酬はテストの合否に、道具を効率よく使った分の小さなボーナスを加えたもの

- 学習中は safeagents という見張りで怪しい道具の呼び出しを止めた

## 4. Zenn：Claude Code の開発手順（2026年11月）。書くのはAI、疑うのは経緯を知らない別のAI、commit と push は自分で
